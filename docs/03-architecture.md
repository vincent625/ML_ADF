# Implemented architecture

The repository contains four complementary components with separate entry points:

- `src/requirements/`: upstream deterministic parser for numbered ticket Markdown and artifact-name traceability. It emits pending requirements and unresolved test mappings.
- `adf-sentinel/`: historical collection, provenance, weak labeling, exploratory fitting, narrow checked file operations, and recorded results. The upload copy includes source and curated reports; full private study inputs and model binaries remain excluded.
- `adf-review-workbench/`: local HTTP viewer, four sanitized evidence packets, seven pending change records, completeness checks, label audit and timing pilot.
- `irs-65265-review/`: synthetic review, patch, retest and stale-evidence demonstration with independent contracts and observed fixture bytes.

The top-level README diagram distinguishes implemented local connections from manual handoffs and future adapters. No source code was added that automatically converts a traceability matrix or model suggestion into an executable plan. Current checkers and generators have different schemas and scopes.

All default demos use local files. Source collection requires separately authorized source access. The recommended workbench and requirements quick starts use only the Python standard library. Sentinel model tests require its locked dependency stack. Real core assembly, software/scientific testing, physical validation and release publication require additional tooling and evidence.

Package checksums validate the delivered files, while dated original receipts describe prior runs. A partial upload copy cannot prove that every excluded private input is available or unchanged on another machine.
